# 멀티탭

질문 하나를 여러 AI에게 동시에 던지고, 답을 나란히 놓고 보는 앱.
브라우저 탭처럼 **AI 하나 = 탭 하나**. 한 창에 최대 7개까지 연다.

```bash
npm run dev
```

`http://localhost:3000` — API 키가 없어도 모의 응답으로 전부 동작한다.

## 세 개의 방

왼쪽 사이드바에 방이 셋 있다.

| 방 | 하는 일 |
| --- | --- |
| **질문** | 그냥 대화한다. 다만 답하는 쪽이 여럿이다. 태도는 입력창 아래에서 고른다 |
| **법원** | 싸운 두 사람을 앉혀 놓고 AI 대리인 둘이 대신 싸운다 |
| **위로** | 성격이 완전히 다른 친구 다섯이 있는 단톡방에 사연을 던진다 |

### 기본은 그냥 대화다

이 앱은 특별한 도구가 아니라 **그냥 채팅**이다. 다만 답하는 쪽이 여럿일 뿐이다.
아무거나 물어보면 열린 AI 전부가 각자 답한다. 그게 전부고, 그게 기본값이다.

레드팀이니 인비즈니 하는 건 **필요할 때 켜는 것**이지 출발점이 아니다.
그래서 셋을 방으로 나누지 않고 입력창 아래에 고르개를 뒀다 —
GPT의 모델 고르개가 있는 그 자리.

| 태도 | 하는 일 | 입력창이 어떻게 변하나 |
| --- | --- | --- |
| **대화** | 기본값. 그냥 물어보면 전부가 답한다 | 한 줄짜리 상자 |
| **레드팀** | 전부 투자 심사역이 된다. 깨질 지점만 찾는다 | 크기는 같고 잉걸빛이 붉게 돈다 |
| **인비즈** | 대표 AI가 부서를 편성해 검진표 한 장으로 돌려준다 | 상자가 자라고, 보내기가 「법인 세우기」가 된다 |

고르면 배경 온도, 초점 테두리, 보내기 버튼이 같이 따라간다.
**쓰던 글과 하던 대화는 그대로 남는다** — 버릴 거면 그건 고르개가 아니라 그냥 다른 방이다.

「서로 반박시키기」와 「정리하기」는 답이 쌓인 뒤에만 나타나는 버튼이다.
대화에 얹는 것이지 대화의 전제가 아니다.

## 되는 것

- **동시 질문** — 열려 있는 탭 전부가 같은 질문에 각자 답한다. 병렬 스트리밍이라 빠른 모델부터 먼저 찬다.
- **하나의 대화** — 모든 탭이 같은 맥락을 본다. 이전 턴에서 다른 AI가 뭐라고 했는지까지 포함해서.
- **토론 붙이기** — 열린 탭끼리 서로의 답을 읽고 이름을 대며 반박한다. 라운드는 누적된다.
- **탭 보기 / 비교 보기** — 넓으면 열로 나란히, 좁으면 단체 대화방처럼. 묻지 않고 화면 폭으로 정한다.
- **기록** — 돌린 것은 왼쪽에 쌓이고, 누르면 그 화면이 그대로 돌아온다. 브라우저에만 저장된다.
- **⌘K** — 방 이동, 기록 열기, 새로 시작. 셋뿐이다.

## 법원

시작 화면에 있는 건 두 개다. 어떤 법정이냐, 시작할 거냐.
사건명이니 이름이니 하는 건 들어가서 재판장이 물어본다.

```
재판장   개정합니다. (…) 남자, 진술하시오.
남자     ← 여기서 멈춘다. 적을 때까지 기다린다.
재판장   잘 들었습니다. 여자, 반박하시오.
여자     ← 또 멈춘다.
남자 대리인   재판장님, 3초짜리 손가락 운동과 문장을 고르는 노동은…
여자 대리인   GPT-4o 대리인, 방금 3초가 있었다고 본인 입으로 말했습니다.
남자 대리인   Google 모델다운 답변이군요.
…
재판장   거기까지. 배심원단, 평의하시오.
```

한 번에 한 명만 말한다. 앞사람 말을 읽고 다음 사람이 들어온다.
말은 전부 세 문장 이내다 — 여기는 채팅이지 준비서면이 아니다.

**대리인은 상대 AI를 이름으로 깐다.** 상대가 어떤 모델이고 어느 회사가 만들었는지 알고 들어간다.
마지막에 배심원 다섯이 점수를 매기고, 재판장이 과실비율과 형을 선고한다.
형은 징역이 아니라 관계에서 집행 가능한 것이다 — *2주간 스토리 올리기 전에 답장 먼저 보낼 것* 같은.

**판결에 불복하면 항소한다.** 양측 대리인을 맞바꿔 변론부터 다시 하는 것이고, 대체로 판결이 뒤집힌다.

### 두 개의 법정

- **일반** — 말투는 법정, 내용은 코미디. 욕설은 없다.
- **19금** — 대리인들이 욕하면서 싸운다. 상대 AI 모델까지 걸고 넘어간다.

```
여자 대리인   지랄 마라. GPT-4o야, 잠긴 화면에서 좋아요가 눌리냐?
남자 대리인   Google 모델 따위가 그것도 애정이라고 계산하고 앉아 있네요.
```

열기 전에 나이 확인을 한 번 받는다. 19금에서도 혐오 표현과 노골적인 성적 묘사는 나오지 않는다 —
욕은 상황과 상대 논리에 대고 하지 사람을 걸고 넘어지지 않는다.
바로 눌러볼 수 있는 데모 사건이 다섯 개 있다. 양쪽 진술이 채워진 채로 끝까지 자동으로 굴러간다.

## 위로

단톡방 하나에 성격이 완전히 다른 친구 다섯이 앉아 있다.
다섯이 다 착하면 위로가 안 되기 때문이다.

| 친구 | 성격 |
| --- | --- |
| 다정이 | 일단 네 편. 감정부터 받아준다 |
| 불꽃이 | 먼저 화내준다. 판을 키운다 |
| 현실이 | 팩트만 던진다. 위로는 남의 일 |
| 바른이 | 옳은 쪽을 고른다. 네가 틀리면 너한테도 그런다 |
| 뒤집이 | 굳이 반대편에서 본다 |

친구마다 다른 모델이 붙는다. 같은 모델 다섯이면 성격도 결국 하나가 되기 때문이다.
한 명씩 순서대로 들어온다 — 감정이 먼저 오고, 흥분이 붙고, 그 다음에 찬물이 끼얹어진다.
첫 사연에는 다섯이 다 붙고 그 뒤로는 셋만 붙는다. 실제 단톡이 그렇다.
두 번째 턴부터는 서로를 걸고 넘어진다 — *"뒤집이 넌 왜 자꾸 저쪽 편을 들어."*

## 만든 방식

화면은 어두운 판이 아니라 빛이 지나가는 종이다.
아래 어딘가에 따뜻한 광원이 하나 있고, 위에서는 차가운 진주빛이 들어온다.
그 사이에 유리를 띄운다.

재료는 두 가지뿐이다.

- **유리** — 떠 있는 것. 패널, 팝오버, 말풍선, 입력창.
  `.glass` `.glass-2` `.glass-3` · 본문 판은 `.sheet`, 위에 뜨는 창은 `.glass-modal`
- **자기** — 놓여 있는 것. 눌린 자리, 본인이 직접 한 말, 명패. `.nm` `.nm-in` `.nm-btn`

밝은 바탕 위의 유리는 어두운 바탕 위의 유리와 정반대로 만든다.
바탕보다 **밝게** 채우고, 흐리기와 함께 **채도를 올린다**. 채도를 안 올리면 그냥 흰 상자가 된다 —
뒤가 비쳐야 유리다. 그래서 화면을 거의 다 덮는 `.sheet`는 제일 얇게 채우고 제일 세게 흐린다.
테두리에서는 색이 갈라진다(`.glass-lit`) — 복숭아, 라일락, 박하. 진짜 유리는 가장자리에서 빛을 쪼갠다.

**그림자는 검정이 아니라 갈색이다**(`--shadow-warm`). 따뜻한 빛이 만드는 그늘은 따뜻하다.
이 하나가 화면 전체의 온도를 정한다.

색으로 꾸미지 않는다. 색은 역할을 구분할 때만 쓴다.
잉걸빛(`--color-accent`)은 화면에 하나뿐이다 — 보내기 버튼. 나머지는 전부 양보한다.
모드 이름이 그대로 배경의 온도가 된다: 인비즈는 서늘한 박하, 레드팀은 뜨거운 주홍,
법원은 놋쇠, 위로는 장미. 전환은 1.6초에 걸쳐 아주 느리게 옮겨간다.
판결문만 명조를 쓴다 — 명조는 밝은 종이 위에서 제 얼굴이 나온다.

첫 화면은 시간에 맞춰 한 마디 하고, 열려 있는 AI를 점으로 보여준 다음, 큰 글씨 두 줄로 끝난다.
설명하지 않고 보여준다.

폰에서는 떠 있는 카드를 포기하고 화면 끝까지 붙인다. 여백 10px보다 본문 10px이 낫다.
대신 노치와 홈 인디케이터는 피하고, 손가락으로 눌러야 하는 것은 전부 커진다.
대화창은 바닥에 붙어 따라 내려가되, 위로 올려 다시 읽는 중이면 끌어내리지 않는다.

본문·라벨·놋쇠·잉걸 전부 밝은 바탕에서 WCAG AA(4.5:1)를 넘게 잡았다.
모델·부서·친구 식별색도 같은 기준으로 한 단계씩 깊게 내렸다 — 어두운 판에서 빛나던 색은
종이 위에서 형광펜이 된다.

## API 키

`.env.example`을 `.env.local`로 복사하고 있는 키만 채우면 된다.
키가 있는 provider만 실제로 호출되고, 없는 쪽은 자동으로 모의 응답으로 넘어간다.
섞여 있어도 된다 — 실제 응답 옆에 모의 응답이 나란히 서고, 모의인 쪽에는 `모의` 표시가 붙는다.

| provider | 환경변수 |
| --- | --- |
| Anthropic | `ANTHROPIC_API_KEY` |
| OpenAI | `OPENAI_API_KEY` |
| Google | `GOOGLE_GENERATIVE_AI_API_KEY` |

모델 목록과 호출용 id는 [lib/models.ts](lib/models.ts) 한 곳에만 있다. 모델을 바꾸거나 추가하려면 거기만 고치면 된다.

## 구조

```
app/
  page.tsx             껍데기 — 사이드바 · 머리 · 질문 방(태도 셋)

  api/inbiz/route.ts   법인 단계별 스트리밍
  api/court/route.ts   법정 — 한 요청에 한 사람만 말한다
  api/comfort/route.ts 위로방 — 친구 한 명씩
components/
  shell/               사이드바 · ⌘K 팔레트 · 태도 고르개 · 설정 · 아이콘
  court/               시작 화면 · 법정 대화 · 판결문
  comfort/             단톡방
  inbiz/               조직도 · 부서 보고 · 검진표
  TabStrip.tsx         탭 스트립과 탭 추가 메뉴
  Thread.tsx           대화 — 비교 보기(열 분할) / 탭 보기
  Composer.tsx         입력창 — 태도에 따라 모양과 색이 변한다
lib/
  models.ts            모델 7종 정의
  chat.ts              대화·레드팀 타입과 프롬프트
  court.ts             배역 · 단계 · 판결 파싱 · 프롬프트
  comfort.ts           친구 다섯의 성격과 프롬프트
  inbiz.ts             부서 카탈로그와 단계별 프롬프트
  useTabs.ts           탭 · 대화 상태와 스트림 처리
  useCourt.ts          재판 진행 (개정 → 진술 → 변론 → 선고)
  useComfort.ts        단톡방 진행 (한 명씩 순서대로)
  useInbiz.ts          법인 진행 (편성 → 진단)
  sessions.ts          기록 저장소 (localStorage)
  mock.ts              키 없이 돌리기 위한 모의 응답
  courtMock.ts         사건 종류 × 등급별 모의 법정 기록
  comfortMock.ts       사연 종류 × 친구별 모의 답장
  inbizMock.ts         업종별 모의 진단
```

## 알려진 한계

- 기록은 이 브라우저에만 남는다. 다른 기기에서는 보이지 않고, 저장소를 비우면 사라진다.
- 모의 응답은 질문 내용을 실제로 이해하지 않는다. 화면과 흐름을 보기 위한 것이다.
- 모의 대본은 사건·사연 종류를 키워드로 짐작한다. 어디에도 걸리지 않으면 일반 대본으로 간다.
- OpenAI · Google 모델 id는 예시값이다. 계정에서 쓸 수 있는 id로 `lib/models.ts`에서 바꿔야 한다.
